# Status

**Current version:** `0.3.0` public release candidate

**Maturity:** Level 0 — Blueprint

**Authority:** default deny; reference-only; non-operational

## Current objective

Prepare a clean, licensed, evidence-honest public source candidate for the adaptive,
platform-neutral 0.3 blueprint. No target repository, model, harness, runtime, evidence
authority, promotion, or publication is activated by this work.

## Completed surfaces

- Platform-neutral build/observe/evaluate/error-analysis methodology derived from the
  reviewed research sources.
- Orthogonal project maturity, task rigor, and effect authority.
- Four task-rigor profiles: `light`, `bounded`, `evaluated`, and `assured`.
- Claim/effect/evaluator-aware evidence modules that keep runtime and rollback evidence
  conditional rather than treating them as profile-wide ceremony.
- Portability corrections from four bounded observations in a separate reference project:
  evaluator maturity is per claim; exact regressions, program execution, and AI
  participation no longer over-escalate neighboring deterministic claims.
- A genuine lightweight path that needs no formal JSON record when an issue/prompt and
  existing deterministic check are sufficient.
- Optional strict component contracts for cross-context or high-consequence autonomous
  work; the unverified integrated agentic-episode composition is preserved only as a
  non-normative draft.
- Exact cloud/local model+harness subjects, small-context worker packaging, compact
  orchestrator receipts, a first-class bounded worker packet, coding-versus-inference
  subject separation, and empirical qualification contracts for repeated autonomy.
- Provider- and platform-neutral schemas, registries, inert templates, synthetic
  examples, and dependency-free validators.
- Reusable evaluator calibration, path-security, context/authority, protocol-security,
  adoption/efficacy, resource, and lifecycle conformance.
- A closed-world 44,100-tuple lifecycle domain with 33 admitted rows, a separately
  implemented rule predicate, focused aggregate/shape/mutation vectors, and documented
  cost/value assessment.
- An authenticated explicit Level 0 release inventory.
- Human-decision, operations/learning, threat, provenance, and progressive-adoption
  guidance.
- A compact mixed deterministic/semantic example with proportional generator sampling,
  causal stopping, and an explicit model-judge versus external-human boundary.
- An Apache-2.0 code-and-documentation license, verified research attribution, exact CI
  dependency pins, a clean-history publication boundary, and a short first-run path.
- A candid empirical-status statement that separates internal conformance, portability
  observations, and untested operational claims.

## Design lineage

Version 0.3 began with a maximum-assurance design that made its strongest machinery look
too universal. The revision preserved reusable contracts, restored one path grammar,
made lifecycle comparison genuinely differential, added adaptive rigor and a real light
path, and demoted the integrated episode artifacts to non-normative drafts because no
semantic composition validator supports an assured claim.

## Historical baselines

- `0.1.0`: initial Level-0 design that exposed authority and evidence-contract defects.
- `0.2.0`: green hardened protocol baseline and compatibility predecessor to 0.3.

The development history is not part of the first public source branch. The public branch
must start from the verified sanitized 0.3 tree so removed pre-publication terminology is
not accidentally republished.

## Not implemented or authorized

- Operational packet compiler or semantic admission service.
- Semantic integrated agentic-episode composition validator.
- Concrete cloud/local capability certificates.
- Candidate/worktree manager.
- Real lease/fencing backend.
- Provider, model, MCP, CLI, engine, database, deployment, or runtime adapters.
- Real evidence-acceptance or human-review service.
- Target-repository gate transitions.
- Promotion or publication contracts.
- External repository, model, target, runtime, or network operation.

A green Level-0 suite proves only the reference artifacts. Four small portability
observations supply bounded adoption evidence for the methodology, but their corpus is
not distributed here and they do not prove an arbitrary target adapter, authoring tool,
runtime harness, or target authority. See `docs/EMPIRICAL_STATUS.md`.

## Remaining release steps

1. Complete all dependency-free checks and exact release-bundle generation.
2. Freeze the sanitized candidate to an exact local commit.
3. Create a clean root public branch and verify it from an isolated exported tree.
4. Run one bounded open-source-readiness review and correct only material findings.
5. After publication is separately authorized, require every hosted CI matrix cell to
   pass for the exact public commit before tagging a release.
6. Enable private vulnerability reporting or document another private reporting channel.

Downstream adoption and any operational implementation remain separate owner decisions.
