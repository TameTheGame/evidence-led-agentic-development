# ELAD v1.05 — S&box start-up guard, a clean-up check, and 27 more import lessons

The second batched release. It brings a batch of updates to the S&box example: a guard
that stops the editor check hanging on S&box's start-up error box, a check for clearing out
generated files, three new sections in the S&box guide, and 27 more entries in the import
reference. No skill changed.

## Highlights

- **The editor check no longer hangs on S&box's start-up error box.** When the Editor
  can't start a project, it shows an error box and waits for a click.
  [`examples/sbox/tools/editor_check.ps1`](../examples/sbox/tools/editor_check.ps1) now
  watches for that box and for the failure in the editor log. On either, it saves the
  box's text to `error-box.txt`, closes the editor and the box, and stops with `NOT RUN` in
  seconds. The guide's new section,
  [When S&box can't start a project](../examples/sbox/README.md#when-sbox-cant-start-a-project),
  says what sets the box off and how any script that starts S&box should guard against it.
- **A check for clearing out generated files.**
  [`examples/sbox/tools/scene_refs.py`](../examples/sbox/tools/scene_refs.py) lists each
  file in a folder as in use or unused by a project's scenes and prefabs, comparing paths
  the way S&box does, and fails when a scene or prefab references a file that isn't there.
  It deletes nothing. The guide's new section,
  [Clearing out generated files](../examples/sbox/README.md#clearing-out-generated-files),
  uses it to move old bakes aside safely.
- **Throwaway projects.** The guide's new section,
  [Throwaway projects](../examples/sbox/README.md#throwaway-projects), says that opening a
  project in the Editor adds it to S&box's project list, and how to clear a scratch
  project away.
- **27 more S&box import lessons** in
  [`examples/sbox/IMPORTING.md`](../examples/sbox/IMPORTING.md), on lighting (Source lamp
  falloff, light volumes for each lamp state, `$selfillum` and glowing textures, exposure,
  normal maps, live in-world screens), physics and collision, Source's sound fade and
  levels, cameras, moving brushes without judder, `sbox-cli` timeouts, input actions,
  `run_csharp` scripts, and playing a map inside Facepunch's Sandbox as one addon project.
  Several existing entries gained detail, among them keeping a player awake on a moving
  floor and what turning auto exposure off drops.
- **More notes in the guide.** Check motion on the screen by recording the game window,
  and read the screen's real size on Windows, where a process that isn't DPI aware is told
  a scaled one. A joining client logs small files as missing even when they load. A build
  outside S&box, including the compile check and `dotnet build`, can't catch one compile
  error the Editor's own compile raises.

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged
since v0.8.

- **Update your pin.** A project that names its ELAD version changes it to `1.05` and this
  release's commit. Search for `1.04` as a whole word.
- **Example scripts.** `editor_check.ps1` gained the start-up guard. Its arguments and exit
  codes are unchanged (0 pass, 1 fail, 2 not run), so a project that copied it can take the
  new copy as it is. `scene_refs.py` and its test are new.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later.

## Evidence and limits

- **One project, a few builds.** The new entries and the start-up guard come from one
  project's work on S&box `26.10.13a` and `26.10.13b`, on one Windows machine. S&box
  citations are at `26.10.13`, which is approximate for those builds, and Source citations
  read the Source SDK 2013, not Garry's Mod's own fork.
- **The start-up guard ran on this machine,** in Windows PowerShell 5.1 and PowerShell 7,
  against two projects that can't start and one made from S&box's template. It hasn't met
  every way a start can fail.
- **`scene_refs.py` passes its own test** on a throwaway project laid out like a real one,
  and fails its controls. It hasn't yet run on a real project.
- **Some entries are read from source or seen only,** or have "nothing yet" as their
  proof, and say so. The note on the Editor-only compile error is read from the source at
  `26.10.13` and `26.10.27` and wasn't run.
- **No acting-session test ran.** The skill evidence is the same as in v0.8.

## Rollback

Pin `v1.04`. Nothing in a project changes unless its owner adopts v1.05.
