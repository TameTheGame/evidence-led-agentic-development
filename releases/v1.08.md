# ELAD v1.08 — Written hand-offs, an owner gate that can't go quiet, a GPU wait, and two outside reviews

The fifth batched release. The owner may now hand off agreeing requirements in writing, and two skills teach it. The spec lint's owner gate can no longer be lost behind a passing exit code, and the spec format says plainly what closes a requirement. The S&box example's skill, starter and editor check follow two outside reviews: S&box starts wait for a free GPU, the editor check puts back every file a save writes, and the guide gains a set of lessons. Three skills changed, each after a blind pressure test.

## Highlights

- **An owner may hand off agreeing requirements, in writing.** [ADR-0022](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/docs/DECISIONS.md#adr-0022--an-owner-may-hand-off-agreeing-requirements-in-writing) lets the owner name the requirements or area a hand-off covers and when it ends. Each requirement agreed under it carries an `agreed-by` line quoting the owner, and the owner gate still reports it. [`asking-the-owner`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/skills/asking-the-owner/SKILL.md#a-written-hand-off) teaches it, and says vague consent such as "decide on my behalf" isn't one. In the [hand-off test](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/skills/evidence/HANDOFF_TEST.md), only the updated skills recorded the hand-off in each requirement.
- **The owner gate can't go quiet.** [`spec_lint.py`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/tools/spec_lint.py) gains `--owner-exit`, an exit code of its own for a change that needs the owner or a gate it had to skip. It reports a requirement newly retired, compares a spec new since the base as empty, says so when it had no base, reports a check that doesn't name its ID, and fails a requirement heading it can't read. The [spec format](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/docs/SPEC_FORMAT.md#a-spec-lint-for-projects) says to compare with the last commit the owner has seen and to show the output either way.
- **What closes a requirement, said plainly.** A requirement without `touches` reopens on any change, and `touches` are paths or keys. A card defines its own replies, such as `GO`, `REVISE` and `NO-GO`, and one left unanswered leaves its requirement unmet. Results and acceptance lines may carry the build they ran on.
- **The S&box skill points at the starter.** [`sbox-engine-reference`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/skills/sbox-engine-reference/SKILL.md) now loads saved scenes with the starter's `LoadSavedScene`, finds the default surface in the starter's `TestSurfaces.cs`, looks to `SBOX_PUBLIC` for the engine source, and records a lesson only where `AGENTS.md` says. In the [skill update test](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/skills/evidence/SKILL_UPDATE_TEST.md), its agents asked where a lesson belongs instead of making a file.
- **S&box starts wait for a free GPU.** The new [`wait_for_gpu.ps1`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/tools/wait_for_gpu.ps1) holds an engine test run or an editor start while another program uses the GPU, checking every 5 minutes for up to an hour. See [Waiting for a free GPU](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/README.md#waiting-for-a-free-gpu).
- **The editor check leaves nothing behind.** [`editor_check.ps1`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/tools/editor_check.ps1) puts back the scene's `_c`, `_d` and `.meta` files, names any file a run left changed, fails a first save that rewrites the scene, stops with `NOT RUN` when S&box's build changes during a run, and starts one more editor after a silent stall. It also keeps its quotes in every PowerShell.
- **The starter's runner stops on setups it can't run.** [`run_engine_tests.ps1`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/rung1-starter/tools/run_engine_tests.ps1) stops with `NOT RUN` when the project has no `UnitTests` folder or has moved since the Editor wrote its project files, and gives each run its own results folder. It reads S&box's build, from `.version` and Steam's build ID, before and after the tests, writes both to `build.txt`, and ends `NOT RUN` when they differ, as the editor check does across its sessions. The compile check stops on a script path that matches nothing, and `scene_refs.py` works through linked folders.
- **More S&box and Windows lessons.** The guide lists [what a project copies](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/examples/sbox/README.md#using-this-example-in-a-project), writes its commands so they work in Git Bash, and adds lessons on every eye height a player can reach from, sealing checks, moved projects, reading scene values, Steam installing an update between sessions, a re-save writing new fields, `cmd /c` in Git Bash, the letter case Git keeps for a new file's folder on Windows, reading `PATH` again before calling a tool missing, `Components.Get<T>()` skipping a component on a switched-off object, and the tags a ladder volume and the player's body need.
- **The hosted checks run every example tool's test.** The skill-test harness no longer leaks the condition through step numbers, and no longer counts reading a script as running it. The [release steps](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.08/docs/RELEASING.md#delivery-loop) say to fast-forward `main` with `git merge --ff-only`.

## Compatibility and migration

A spec written to the format needs no change. Three skills changed: `asking-the-owner`, `matching-evidence-to-claims` and the example `sbox-engine-reference`. Take the new copies.

- **Update your pin.** A project that names its ELAD version changes it to `1.08` and this release's commit. Search for `1.07` as a whole word.
- **Example scripts.**
  - `run_engine_tests.ps1` and `editor_check.ps1` need `wait_for_gpu.ps1` beside them, and stop with `NOT RUN` without it. Copy all three. On a machine without `nvidia-smi` the wait goes ahead.
  - `editor_check.ps1` keeps its arguments and exit codes. A first save that rewrites the scene now fails, where it was a note: open the scene in the Editor once, save it, and commit what S&box writes, as `26.11.03a`'s new fog fields need.
  - `run_engine_tests.ps1` keeps its arguments and exit codes. A project with no `UnitTests` folder, or with project files that name paths that aren't there, now stops with `NOT RUN`; open the project once in the Editor to fix the second. A run whose S&box build changed under it also ends `NOT RUN`, and its results gain `build.txt`.
  - `spec_lint.py` keeps its arguments, adds `--owner-exit`, and fails a `###` heading under `## Requirements` that isn't shaped as a requirement. Its new `NEEDS OWNER` and `NO ID` lines are reported, not failures.
  - `compile_check.ps1` stops with `NOT RUN` on a `-Scripts` entry that matches no file.
  - The skill-test runners now need PowerShell 7.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later. They were last run on `26.11.03a`.

## Evidence and limits

- **Two blind pressure tests, small samples.** The skill update test ran 12 sessions and the hand-off test 18, with three runs per cell, one model, one harness, and Windows only. In the skill update test the scene-loading change made no difference, since every run used the starter's helper.
- **The GPU wait ran on one PC.** It held while two GPU jobs ran, went ahead once they stopped, and left out an impossible figure Windows gave for NVIDIA's overlay.
- **Some new paths are exercised only by planted cases.** The editor check's stall retry hasn't met a real stall, and its note on files left unrestored has no self-test.
- **The lessons come from one project's work** on S&box `26.10.27c` to `26.11.03a`, on one Windows machine. Source citations read the source at `26.10.13` and `26.10.27`, approximate for those builds, and some lessons are read from the source and not run, and say so.

## Rollback

Pin `v1.07`. Nothing in a project changes unless its owner adopts v1.08.
