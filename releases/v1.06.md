# ELAD v1.06 — Stricter engine test results, a .meta check, and 20 world-build lessons

The third batched release. It brings the S&box example an engine test runner that no longer reads a run that proved nothing as a pass, an editor check that copes with store packages, a static check for `.meta` files, and twenty world-build lessons in the S&box guide. ELAD's Python tools now write UTF-8 on any pipe. No skill changed.

## Highlights

- **An engine test run that proved nothing no longer passes.** `dotnet test` exits 0 when every test stops with `Assert.Inconclusive`. [`run_engine_tests.ps1`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/examples/sbox/rung1-starter/tools/run_engine_tests.ps1) now reads each test's outcome from the run's results file and ends with one `Result:` line: `PASS` only when at least one test ran and every test passed, `FAIL` on a failure, and `INCONCLUSIVE` when a test didn't run or none ran. It also stops a run at its time limit, 30 minutes by default, and kills everything the run started.
- **The editor check sets store package IDs aside.** S&box can give a store package's files new IDs in each editor session, and then the resave check failed a scene that used one. [`editor_check.ps1`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/examples/sbox/tools/editor_check.ps1) now reads each session's IDs with the new [`package_ids.cs`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/examples/sbox/tools/package_ids.cs) and sets an ID aside only when it is exactly the one that session gave the path. Every other byte still has to match.
- **A static check for `.meta` files.** [`check_metas.py`](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/examples/sbox/tools/check_metas.py) fails each file Git tracks under the assets folder that has no `.meta` beside it, so a missing one fails before an editor run instead of in it. The guide's `.meta` lesson now says to commit new sources with their `.meta` files before the build.
- **Twenty world-build lessons** in the guide's new section, [More world-build lessons](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/examples/sbox/README.md#more-world-build-lessons). Among them: allow for a store package's ID changing between sessions; wait with a limit for a compiled file, and don't take `Compile`'s result as the verdict; compare read-back rotations with atan2; load a sound with `LoadAsync` before reading its length; set a picture compare's threshold from runs; put back what a failed build wrote; set a decal's roll to a constant; and put a map's `Fog` where no camera or post-process volume owns it, since on `26.10.27` one with no owner fogs every camera.
- **A hold on files built from an input the owner adopted.** The [spec format guide](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/docs/SPEC_FORMAT.md#a-spec-lint-for-projects) suggests a lint that holds what a project builds from such an input, such as a plan, to the commit that last pinned the input's SHA-256, and lets it change only in a commit that pins the new input and records the owner's answer.
- **UTF-8 output.** ELAD's Python tools and their tests write UTF-8 on any console or pipe. On Windows, a pipe in the ANSI code page used to garble their text or stop them with a traceback in place of their report.
- **Releases go out under the owner's standing approval,** with release notes and no GREEN for each one. See [Releasing](https://github.com/TameTheGame/evidence-led-agentic-development/blob/v1.06/docs/RELEASING.md#release-cadence).

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged since v0.8.

- **Update your pin.** A project that names its ELAD version changes it to `1.06` and this release's commit. Search for `1.05` as a whole word.
- **Example scripts.**
  - `run_engine_tests.ps1` keeps its arguments and gains `-TimeoutSeconds` and `-SelfTest`. It now exits 0 pass, 1 fail, or 2 inconclusive or not set up; it used to exit with `dotnet test`'s own code, which is 0 for an inconclusive run. A wrapper that reads any non-zero exit as a failure needs no change.
  - `editor_check.ps1` needs `package_ids.cs` beside it; take both. Without it, the check says so and compares store package IDs as written, as before. It gains `-SelfTest`; its other arguments and its exit codes are unchanged.
  - `check_metas.py` and its test are new. `spec_lint.py`, `scene_refs.py` and `check_metas.py` write UTF-8, so a script that reads their output reads it as UTF-8.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later. The fog lesson needs `26.10.27`, where `Fog` first appears.

## Evidence and limits

- **One project, a few builds.** The lessons and fixes come from one project's world work on S&box `26.10.13a` to `26.10.27c`, on one Windows machine. S&box citations read the source at `26.10.13` and `26.10.27`, approximate for those builds.
- **The engine test runner ran on `26.10.27c`:** seven passing tests gave `PASS`, a missing scene and a filter that matched nothing gave `INCONCLUSIVE`, and a 5-second limit killed the run's whole tree.
- **The editor check's ID compare is exercised only by planted saves.** On `26.10.27c` the store model it re-saved kept its ID in every session. In another project on that build, a store material's ID did change between sessions.
- **`check_metas.py`** passes its test, which fails on each of eight planted faults, and agreed with one real project's own check.
- **Some lessons are read from the source and not run,** and say so. The fog lesson is read at `26.10.27` only.
- **The owner-input hold** comes from one project's lint. ELAD ships no example of it.
- **No acting-session test ran.** The skill evidence is the same as in v0.8.

## Rollback

Pin `v1.05`. Nothing in a project changes unless its owner adopts v1.06.
