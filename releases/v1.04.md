# ELAD v1.04 — Batched releases, and 32 more S&box import lessons

The first release made under the new cadence: finished changes collected on one branch
and ship together. It adds 32 entries to the S&box import reference and corrects two. No
skill changed.

## Highlights

- **Releases come in batches.** Finished changes collect on `tamethegame/next-release`,
  each with a changelog line under `Unreleased` and no version bump, and `main` moves only
  at release time. A release is due when the batch has something a user would notice, and
  it goes out on one GREEN from the owner, in the evening and not every day. An urgent fix
  lands on the branch too and ships the batch early. See
  [Release cadence](../docs/RELEASING.md#release-cadence) and ADR-0021 in
  [Decisions](../docs/DECISIONS.md).
- **32 more S&box import lessons** in
  [`examples/sbox/IMPORTING.md`](../examples/sbox/IMPORTING.md).
  - Twenty on physics, collision, water and movement: building ragdolls at run time,
    keeping a Source collision model's convex pieces, taking brush entities' collision
    and mass from the BSP, displacement ground, mass, impact breaking, hinge friction, air
    drag, surfaces with sounds, water, ladders, lifts, and registering files the Editor
    didn't make. "Ask the original game what it does" now says how to measure physics and
    record ragdoll poses, and a new entry says to run a case with the fix off before
    writing a fix.
  - Twelve more on props the player carries, breakable brushes, radius damage, traces that
    start inside a collider, soundscapes, sound loops, underwater sound, `func_breakable`
    sounds, `trigger_hurt`, what a breaking entity takes with it, playing a map inside
    Facepunch's Sandbox, and 3D skyboxes, under a new "World geometry" section. The
    impact-damage entry is clearer about mass and impact speed.
- **Two entries corrected.** Radius damage now gives the 1.25 explosion scale to
  `func_physbox` as well as `func_breakable`, and the entry on traces that start inside a
  collider no longer says how Source's trace treats one.

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged
since v0.8, and no example script changed.

- **Update your pin.** A project that names its ELAD version changes it to `1.04` and this
  release's commit. Search for `1.03` as a whole word.
- **Projects pin released tags,** so batching changes nothing for them.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later.

## Evidence and limits

- **One project, one build.** The new entries come from one project's import of an old
  Source 1 map on S&box `26.10.13a`, on one Windows machine. S&box citations are at
  `26.10.13`, which is approximate for that build, and Source citations read the Source
  SDK 2013, not Garry's Mod's own fork.
- **Some entries are seen only,** or have "nothing yet" as their proof, and say so.
- **The cadence is a policy, not a measured result.** This is its first release.
- **No acting-session test ran.** The skill evidence is the same as in v0.8.

## Rollback

Pin `v1.03`. Nothing in a project changes unless its owner adopts v1.04.
