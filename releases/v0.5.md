# ELAD v0.5 — Direct and Conserve

This release packages the Direct/Conserve delivery update and the consolidated public
blueprint, and closes the gap between pushing source changes and publishing a release.

## Highlights

- Direct lets a capable primary agent own implementation, checks, causal repairs, and
  completion within the authorized outcome. Ordinary tasks do not require a local worker,
  mandatory packet, or separate model for every role.
- Conserve remains an explicit route to an eligible cheaper/local subject. Existing
  worker isolation, budgets, qualification, protected checks, and historical evidence are
  preserved; the same acceptance threshold applies in either mode.
- Context is selected for the task. Assurance budgets, claim-scoped revalidation,
  trustworthy checks, human-only evidence, and owner authority remain in force.
- Blueprint development uses one canonical public repository. Retired pre-publication
  history is private recovery material, not a second maintained blueprint.
- New versions use two components: v0.5, v0.6, and so on. Authorized user-facing updates
  now include a versioned GitHub Release by default, with publication gated on hosted
  conformance and checked-in release notes.

## Compatibility and migration

All active protocol, schema, registry, template, example, vector, bundle, and validator
identities advance together to exact `0.5`. Version-reference fields now require two
numeric components; other structural contracts remain unchanged. Mixing old and new
identities is still rejected. The preserved integrated-episode drafts
remain non-normative 0.3 artifacts and are excluded from the authenticated bundle.

Existing `v0.3.0` and `v0.4.0` tags are unchanged. Targets retain their current pins until
their owners explicitly adopt v0.5 and rerun the checks affected by delivery-mode and
identity changes. This release does not repin or activate any target. Rollback is continued
use of the prior exact release, never rewriting a tag or combining protocol versions.

Validator entrypoints now use the `v05` suffix and the conformance guide is
`docs/PROTOCOL_05_CONFORMANCE.md`. The stable aggregate commands remain
`python tools/validate_all.py` and `tools/Test-Blueprint.ps1`.

## Evidence and limits

The dependency-free suite checks the authenticated inventory, synthetic contracts,
continuation chain, path/security/lifecycle controls, and release-metadata/tag agreement.
Publication is gated on the exact tag's six-cell Windows/Ubuntu/macOS Python 3.10/3.12
matrix. The release tag identifies the source and the associated workflow records its
hosted evidence.

ELAD remains a Level 0, default-deny, non-operational reference blueprint. This release
adds no new empirical model comparison, savings claim, target adapter, runtime permission,
or generic deployment/promotion/publication capability. The repository release job only
publishes this blueprint's own versioned source release.
