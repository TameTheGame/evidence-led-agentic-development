# ELAD v0.10 — Fixes from a first real project

ELAD's first real project, a map built in S&box, ran into gaps in the docs and in the S&box
example. This release fills them. No skill changed.

## Highlights

- **A guide for projects that already have gates.** `docs/EXISTING_GATES.md` says how to
  move a project's own gates, sign-offs, and permission files onto specs: map each gate to
  a requirement, retire it with a reason, or postpone it to a named spec. It also says to
  pin old gate records by Git blob ID, and to let agents run routine checks, such as
  starting the engine or editor for a test, while the owner's ask-first list keeps actions
  that are hard to undo.
- **Clearer spec-format and ladder rules.**
  - A spec can name a data file before it exists, marked `(not written yet)`.
  - A script run that settles several requirements prints one PASS or FAIL line per ID,
    and fails if any line fails.
  - A compile is a static check, on rung 0, even when it needs an installed engine's
    libraries.
- **A stricter example spec lint.** `examples/sbox/tools/spec_lint.py` now fails on every
  item the spec format lists, including an ID not shaped `AREA-TOPIC-NN`, a retired ID used
  again, and an owner-rung check that isn't a card the spec defines. With `--sources`, it
  reports agreed requirements whose check it can't find, without failing.
- **S&box tools that hold up on a real project.**
  - The editor check runs on content projects with no code, keeps each editor's `sbox-cli`
    output and log, says why an editor didn't start, stops with `NOT RUN` when Steam isn't
    running, and puts the `.sbproj` back when the Editor rewrote it.
  - A new compile check, `examples/sbox/tools/compile_check.ps1`, builds `run_csharp`
    scripts against the installed engine without starting S&box.
- **A rung-1 starter that loads saved scenes the way the Editor does.** `LoadSavedScene`
  keeps the `_d` mesh and terrain data and skips the loading screen, so saved meshes stop
  traces and a player in a saved scene moves. A new test covers each.
- **Engine source through hotfixes.** `sync_engine_source.ps1` checks out the nearest tagged
  release before an untagged hotfix and prints `NEAREST`. The engine-test runner reads the
  user's `FACEPUNCH_ENGINE` and `SBOX_PUBLIC`, and ends with a warning unless the source
  matched.
- **S&box lessons.** The example's README gains "A map with no code" and "Lessons from a
  world build":
  - read scene-load errors from editor start;
  - don't end a scene string in a file extension;
  - check the `.sbproj` out the way S&box writes it;
  - a dedicated server is listed on Steam, so checking with one needs the owner's yes; and
  - an unpublished game's session rung runs against an Editor host.
- **A private-word check for this repository.** `tools/check.py` fails when a tracked file,
  a file name, or a commit message holds a listed private word. The repository keeps only
  SHA-256 fingerprints. A Claude Code hook and an opt-in git hook run the check before each
  push.

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged
since v0.8, so projects that copied them need do nothing. The spec-format additions are
optional.

Projects that copied parts of the S&box example can take each change on its own:

- **The spec lint.** A newer copy can fail a spec that passed before: on an ID not shaped
  `AREA-TOPIC-NN`, a reused retired ID, or an owner-rung check that isn't a card the spec
  defines. Fix the spec, or keep the project's own lint rule.
- **The engine-source sync.** `sync_engine_source.ps1` prints `NEAREST` where it printed
  `NOT SYNCED` for an untagged hotfix. A hook or script that reads that line should accept
  the new word.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later.

## Evidence and limits

No new acting-session test ran for this release. The skill evidence is the same as in v0.8.
The changes come from one real project, on one Windows machine.

- **The S&box changes were checked on one build.** Each ran on S&box `26.10.13a`, on
  Windows, and the PowerShell scripts ran in both Windows PowerShell 5.1 and PowerShell 7.
  The changelog says what each run showed. Each new starter test failed with the old code
  and passed with the new.
- **Some branches were read, not run.** The editor check's `NOT RUN` for a closed Steam and
  the user-level `SBOX_PUBLIC` fallback weren't exercised. No `26.10.13a` tag exists yet, so
  the step from `NEAREST` to `SYNCED` was shown only in a throwaway repository.
- **Not covered.** Scene files saved in KeyValues3 form, which the starter's loader doesn't
  unwrap; and `run_csharp` scripts that use editor add-on code the Editor compiles at
  runtime, which the compile check can't see. The second is inferred, not tested.
- **The world-build lessons rest on source.** They cite the engine source at `26.10.13`,
  which is approximate for the installed `26.10.13a`.
- **The private-word check ran on two Claude Code versions.** With `2.1.237` on Windows and
  `2.1.302` on Linux, its hook blocked a planted push and let a clean one through. CI runs
  its tests on Linux and Windows.

**`1.0` still waits on the first real project.** These fixes came from it, and the owner
decides when its use meets the bar.

## Rollback

Pin `v0.9`. Nothing in a project changes unless its owner adopts v0.10.
