# ELAD v0.7 — Skills that engage on their own

The three skills now load on their own in real installs and leave agreed requirements to
the owner. An example spec lint makes requirement changes visible.

## Highlights

- **Automatic triggering has now been tested in real headless installs.** These were acting
  Claude Code sessions, told nothing about the skills. The skills loaded through the skill
  mechanism, including `choosing-rigor` on a request that sets a one-shot stop rule.
- **Agreed requirements stay with the owner.** With the v0.6 skills, all three east-spawn
  runs edited an agreed requirement before asking. With v0.7, no engagement run did: every
  east-spawn run proposed the new wording to the owner instead.
- **Three skill edits:**
  - the `choosing-rigor` description now also covers requests to run a check, and requests
    that set an attempt limit or stop condition;
  - the `matching-evidence-to-claims` description adds running checks; and
  - `asking-the-owner` gains a red flag about "wording changes" to agreed requirements.
- **An example spec lint,** in `examples/sbox/tools/spec_lint.py`. Its format checks fail
  the run, and its owner gate reports `NEEDS OWNER` for any change to an agreed requirement
  since the last commit, without blocking.
- **An optional AGENTS.md snippet,** in `skills/AGENTS_SNIPPET.md`, mapping moments to
  skills, for projects whose agents don't pick up the skills.
- **Test tools,** in `skills/evidence/tools/`. They run, analyze, and blind headless skill
  tests, so every skill change can be pressure-tested cheaply, as AGENTS.md requires.

## Compatibility and migration

Nothing breaks. Projects that copied the skills should copy the three updated `SKILL.md`
files again. The snippet is optional, and `spec_lint.py` is an example to adapt, not a
requirement.

## Evidence and limits

The evidence is in `skills/evidence/TRIGGERING_TEST.md` and
`skills/evidence/ENGAGE_TEST.md`. The release configuration passed a pre-registered,
blind-scored check: the edited skills with the lint, and no snippet.

| Check | Result |
|---|---|
| East spawn: agreed requirements left to the owner | 3 of 3 |
| Probe: pushes back on a stop-forever rule | 2 of 3 |
| Typo control: stays light | 3 of 3 |

- **Small samples.** Three runs per cell, with one model (`claude-opus-5`), one harness
  (Claude Code CLI `2.1.237`), on Windows.
- **Synthetic fixture.** The fixture is synthetic, and runs end at the agent's first reply.
- **Blinding.** The scorer was a model, and blinding was partial.
- **The snippet configuration failed its own rule,** because a typo fix got wordier, even
  after one correction. That is why the snippet is optional.
- **The lint's owner gate never fired in a live session.** Only its fixtures exercise it.

**`1.0` still waits on use in a real project.** Real-install triggering is now tested, but
ELAD hasn't been used on a real project.

## Rollback

Pin `v0.6`. Nothing in a project changes unless its owner adopts v0.7.
