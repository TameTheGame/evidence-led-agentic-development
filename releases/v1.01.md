# ELAD v1.01 — Moving to a new release, and S&box lessons

The first release after `1.0`. It adds steps for moving a project to a new release and nine
S&box lessons from the first real project, and it brings back a release for each update,
now with two-digit minor numbers. No skill changed.

## Highlights

- **Steps for moving to a new release.** The README gains "Moving to a new release". The
  owner asks for the move in one line. The agent finds the release the project pins, reads
  the notes for every release since then, takes the changed files, updates every place the
  project names its pin, runs the project's checks, and records the move. Setup step 3 now
  has the agent name the ELAD release in `AGENTS.md`, by version and commit.
- **Nine S&box lessons,** in the example's README. Each cites the engine source at
  `26.10.13` and was seen on `26.10.13a`.
  - Five more in "Lessons from a world build": a `GameObjectSystem` runs in every scene;
    walking can be tested without a keyboard; in a SceneLoaded hook, `Time.Now` is the
    caller's clock; `run_csharp` edits don't mark the scene unsaved, so `save_scene` writes
    nothing; and `Editor.FileSystem.Content` is read-only.
  - Four in a new section, "Lessons from importing old content": convert SMD models
    first; set some properties in a constructor, not an initializer; a mesh marked
    HideInGame still renders in the editor scene; and `Material.Load` doesn't return null
    for a missing file.
  - "The editor check" no longer calls the `HasUnsavedChanges` setter untested.
- **Version numbers after 1.0.** From this release on, the minor number has two digits:
  `1.01`, `1.02`, and so on. Each update that lands on `main` ships as the next release,
  and each waits for the owner's typed GREEN. See [Releasing](../docs/RELEASING.md) and
  ADR-0021 in [Decisions](../docs/DECISIONS.md).

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged
since v0.8, and no example script changed.

- **Update your pin.** A project that names its ELAD version, in `AGENTS.md`, on copied
  files, or in a check, changes it to `1.01` and this release's commit. Search for `1.0` as
  a whole word, because `1.01` starts with it.
- **Version tools.** `1.01` isn't a strict Semantic Versioning number, because of its
  leading zero, and Python's `packaging` reads it as `1.1`. A project that compares ELAD
  versions with such a tool should compare them as text. ELAD itself has no such tool.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later.

## Evidence and limits

- **The lessons rest on source and one build.** They cite engine source at `26.10.13`,
  which is approximate for the installed `26.10.13a`. Each was seen on that build, in one
  project, on one Windows machine.
- **The moving steps come from one move.** A first real project's move from v0.10 to v1.0
  showed the gap. This repository records no move that has used the steps yet.
- **No acting-session test ran.** The skill evidence is the same as in v0.8.

## Rollback

Pin `v1.0`. Nothing in a project changes unless its owner adopts v1.01.
