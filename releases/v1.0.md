# ELAD v1.0 — Used on a first real project

ELAD's two conditions for `1.0` are met. The skills loaded on their own in real installs
(v0.7), and a first real project, a private S&box project, has now used the method from a
pilot to a first world slice that its owner approved. The number means those two conditions
hold; it grants no maturity or authority. No skill changed.

## Highlights

- **A write-up of the first real project.** `docs/EMPIRICAL_STATUS.md` gains "A first real
  project": what helped, what was ignored, and what got in the way, in synthetic terms.
  - The spec format and the ladder helped most: one-page specs, collision checks moved to
    headless engine tests, a routine suite of under 2 seconds, and a check broken on
    purpose that caught a failure for the wrong reason.
  - The skills were installed, but the project's records show no task that used them.
  - What got in the way led to most of v0.10 and to this release's S&box lessons. One gap
    is still open: a project that adapted an example script gets no patch when the script
    changes.
  - A first world slice, an untextured blockout, passed all 18 of its agreed machine checks
    across the static, engine, editor, and session rungs, and its owner approved it.
- **Three more S&box lessons,** in the example's "Lessons from a world build":
  - a dedicated server doesn't mount a library's assets, so keep what it needs in the
    game's own `Assets`;
  - wait for an active scene, not only for loading to end; and
  - a hidden dedicated server doesn't listen on its game port, so a port check reads the
    server's settings and its query port.
- **An AI-attribution check.** `tools/check.py` fails when a commit credits an AI coding
  tool: an author or committer naming one, a trailer such as `Co-authored-by:` naming one,
  a trailer such as `Claude-Session:`, or a "Generated with" line naming one. CI now checks
  out the full history so it sees every commit.
- **Plain hyphens in check output,** which the Windows CI log showed as a replacement
  character before.

## Compatibility and migration

Nothing in the core breaks. The three skills and the example domain skill are unchanged
since v0.8, so projects that copied them need do nothing. The new S&box lessons are text;
no example script changed.

- **Contributors.** `tools/check.py` now fails on any commit that credits an AI coding
  tool, and CI reads the full history. A branch with such a commit needs it reworded before
  it can merge.
- **S&box version.** The S&box tools still need S&box `26.10.13` or later.

## Evidence and limits

- **The real-project evidence is one project.** One owner, one engine, one Windows machine,
  and five days on v0.9 and v0.10. The owner also maintains ELAD, so it isn't independent
  adoption, and one fix reached the project from ELAD's unreleased work at the owner's
  request. The notes were kept by the agents doing the work.
- **It adds nothing to the skill evidence.** The project's records show no use of the
  skills. That evidence is the same as in v0.8: small samples, one model, one harness, and
  Windows only.
- **The slice ran on one machine.** Same-machine play doesn't show that a player on another
  machine or a clean install can join.
- **The new lessons rest on source and one build.** They cite engine source at `26.10.13`
  and were seen on `26.10.13a`.
- **The AI-attribution check** has ten new test cases, which CI runs on Linux and Windows,
  and every commit on `main` passes it.

## Rollback

Pin `v0.10`. Nothing in a project changes unless its owner adopts v1.0.
