# ELAD v0.9 — An unattended editor check for S&box

The S&box example's editor rung now runs without the owner: a script saves a scene in the
Editor, closes it, reopens it, and checks that nothing changed. The older skill-test runners
also keep the test machine's own settings out of test sessions. No skill changed.

## Highlights

- **An editor check,** in `examples/sbox/tools/editor_check.ps1`. S&box `26.10.13` added
  `sbox-cli`, which drives the Editor over a local named pipe. The script uses it to save a
  scene, close the Editor, reopen it, and fail on:
  - unsaved changes as soon as the scene opens;
  - error-level console lines on reopen;
  - any saved object whose name, parent, enabled state, or components changed; or
  - a second save that doesn't write a byte-identical file.

  It keeps a screenshot from a fixed camera before and after, as a record. The outpost
  spec's OUT-SAVE-01 now names this check, and its owner card SAVE-1 is gone.
- **The engine-source sync on a schedule.** The rung-1 starter now suggests an hourly
  Windows scheduled task for `sync_engine_source.ps1`. Steam updates S&box only when S&box
  starts, so an open session misses an update from a launch made by hand.
- **Cleaner test sessions.** `run_skills_test.ps1` and `run_sbox_skill_test.ps1` now pass
  `--setting-sources project,local`, as `run_live_test.ps1` already did, so skills and
  instructions installed for the test machine's user stay out of test sessions.
- **A retired section removed.** `docs/EMPIRICAL_STATUS.md` no longer describes the Harness
  Readiness Suite. The owner retired that companion repository, and nothing in ELAD used it.

## Compatibility and migration

Nothing breaks. The three skills and the example domain skill are unchanged since v0.8, so
projects that copied them need do nothing. The editor check needs S&box `26.10.13` or later.
It is an example to copy and adapt, not a requirement; an owner card still works for the
editor rung.

## Evidence and limits

No new acting-session test ran for this release. The skill evidence is the same as in v0.8.

- **The editor check was verified on one build.** On S&box `26.10.13`, on Windows, in
  Windows PowerShell 5.1 and PowerShell 7, a scratch scene passed in about a minute. A
  control scene with a component that changes its own saved value each time it loads failed
  on the second save, and passed once that object was removed.
- **The screenshot isn't scored.** The script reports how much the two captures differ, but
  the byte-identical save is what shows the scene came back unchanged.
- **Saves are forced.** The Editor skips a save when nothing changed, so the script adds a
  marker object and undoes it first. The Editor then writes the scene out from what it
  loaded.
- **The scheduled sync was checked once.** On 2026-10-14 an hourly task ran the script
  without opening a window, printed `MATCH`, and returned 0.
- **The runner change was checked on one version.** On Claude Code `2.1.237`, with the
  setting, a session saw the project's skill and none of the user's. Results recorded before
  this change stand as recorded.

**`1.0` still waits on use in a real project.**

## Rollback

Pin `v0.8`. Nothing in a project changes unless its owner adopts v0.9.
