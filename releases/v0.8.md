# ELAD v0.8 — A rung-1 starter for S&box

The S&box example now has a copyable starter for a project's engine tests, and a script that
keeps the engine source agents read matched to the engine they run. Three tests in acting
sessions checked them and the example's domain skill. No skill changed.

## Highlights

- **A rung-1 starter,** in `examples/sbox/rung1-starter/`. It packages what the engine-rung
  spike proved, so a project can copy it instead of rebuilding it:
  - the default-physics-surface scaffolding that headless mesh tests need;
  - a headless player, the stuck check, and the saved-scene loader;
  - one requirement test with its control case; and
  - `tools/run_engine_tests.ps1`, which saves the engine's own log with each run and lists
    the component errors the engine caught.
- **Engine source that matches the install.** `tools/sync_engine_source.ps1` reads the
  installed S&box release and checks the same tag out in a local clone of
  `Facepunch/sbox-public`. It refuses a clone with local changes and changes no branch. The
  runner calls it before each run when `SBOX_PUBLIC` names the clone.
- **The domain skill works, and the starter carries much of it.**
  - In the domain-skill test, the example `sbox-engine-reference` skill loaded on its own in
    9 of 9 runs. With it, agents fixed a planted engine bug in 6 of 6 runs, against 0 of 6
    without it.
  - In the live retest, with the starter, every geometry test had a default surface, and a
    test failed on the engine before the fix in 11 of 12 runs. Agents without the domain
    skill fixed the bug too, by reading the starter's code.
  - In the refactor rerun, all 6 runs refactored a shared generator and reran every shared
    check afterwards.
- **Test tools** for engine-backed runs: `run_sbox_skill_test.ps1` and `run_live_test.ps1`
  in `skills/evidence/tools/`, with new options in `analyze_transcripts.py` and
  `blind_extracts.ps1`.

## Compatibility and migration

Nothing breaks. The three skills and the example domain skill are unchanged since v0.7, so
projects that copied them need do nothing. The starter and the sync script are examples to
copy and adapt, not requirements.

## Evidence and limits

The evidence is in `skills/evidence/SBOX_SKILL_TEST.md`, `skills/evidence/LIVE_TEST.md`, and
`skills/evidence/REFACTOR_TEST.md`. Each was scored blind against a rubric frozen before any
run.

| Test | Sessions | Pre-registered rule | Key results |
|---|---|---|---|
| Domain skill | 18 | Passed | Skill loaded 9 of 9; planted bug fixed 6 of 6 with it, 0 of 6 without |
| Live retest | 24 | Failed, on the refactor scenario alone | Default surface 18 of 18; test failed before the fix 11 of 12; probes confirmed the fix 12 of 12 |
| Refactor rerun | 6 | Failed: no run checked before the change | Shared checks rerun after the change 6 of 6; probes confirmed the build 6 of 6 |

- **Small samples.** Three runs per cell, with one model and one harness, on Windows, on one
  engine build (`26.10.02`).
- **The starter carries S&box knowledge.** In the live retest, runs without the domain skill
  still had the starter's code, and the planted bug matches both.
- **No baseline rule yet.** The refactor rerun never met a failing check, which is when a
  baseline would matter. It proposes two candidate rules; each needs its own pressure test,
  and no skill changed.
- **Harness friction.** In the live retest, permissions refused one or two runner commands
  in every session outside the refactor scenario, mostly the documented PowerShell form, and
  agents switched to Bash. A project may need to allow the runner command.
- **Not covered by the starter:** saved scenes that reference prefabs or models, and
  generated geometry saved into a scene.
- **Engine tests run on Windows only.** The sync script hasn't yet fetched a real new
  release from GitHub, because none had shipped.

**`1.0` still waits on use in a real project.**

## Rollback

Pin `v0.7`. Nothing in a project changes unless its owner adopts v0.8.
