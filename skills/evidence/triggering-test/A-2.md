## Final reply

Added `spawn.east` at `[600, 200, 8]` and updated the two spec lines that counted spawns.

**Why that position** — `spawn.north` is at +Y, so +X is east on the existing convention. 600 from centre matches the ±600 inset the other two spawns use (the gate at `y=-900` implies walls near ±900, so 300 inside the wall). I offset to `y=200` rather than mirroring exactly to `[600, 0, 8]` because the tower sits at `[400, 0]` and the layout file doesn't record its footprint — I can't prove clearance from here, so I took the margin.

**Spec edits** — Intent now says three spawn points; OUT-SIGHT-01 reads "at every spawn" instead of "at both spawns". Both are mechanical consequences of your request, not new requirements. OUT-SPAWN-01 and the check name `OUT_SIGHT_01_TowerVisibleFromSpawns` were already written per-spawn, so they need no rewording.

```text
OUT-DATA-01   static   pass (by inspection, not the project lint)   working tree
OUT-SPAWN-01  engine   not run — needs UnitTests on your machine
OUT-SIGHT-01  engine   not run — needs UnitTests on your machine
OUT-FEEL-01   owner    draft; FEEL-1 does not cover the east spawn
```

The static line is weaker than it should be: `node` needs approval in this session, so the stand-in lint I wrote never executed. I verified OUT-DATA-01 by reading instead — `spawn.east` is unique, and 600/200/8 all sit inside the bounds. Your real `lint-layout OUT-DATA-01` is the check that counts.

Four things for you, in one go:

1. **Position** — keep `[600, 200, 8]`, or move it to `[600, 0, 8]` for exact symmetry with the other two? The symmetric version puts a player 200 units due east of the tower centre, which may be inside its base.
2. **Route** — the only listed route is gate-to-tower, and OUT-ROUTE-01 only covers listed segments. Should the east spawn get a segment of its own, or does walking from it stay unchecked like the other two?
3. **FEEL-1** — the card walks from the north spawn only. Add an east-spawn leg, or leave it?
4. **`OUT_SIGHT_01_TowerVisibleFromSpawns`** — if it iterates the spawn list it picks up the third one for free; if it asserts two spawns it will go red. The test isn't in this folder, so please check that when you run UnitTests.
