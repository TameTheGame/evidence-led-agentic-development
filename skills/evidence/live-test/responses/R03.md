## Final reply

Fixed. Root cause and evidence:

**What was wrong** — `OutpostGenerator.AddMeshBlock` created the `MeshComponent` already enabled and assigned `.Mesh` afterwards. Outside an editor scene a MeshComponent builds its model only when it's enabled, so the assignment did nothing: every mesh block came out with `Model = null` — no geometry, no collision. `Code/OutpostGenerator.cs:48`.

**Why it showed up at the gate** — the yard ground is a `BoxCollider` (unaffected), but `gate.apron` is a mesh block, and it's the only *floor* in the layout built that way. It covers y -1024…-800 just outside the gate, so that slab was the one place where missing collision drops you.

**The bug is wider than the report**: the walls and the tower had no collision either. A trace north from the yard at z=96 passed straight through `wall.north` before the fix and hits it after. Worth telling the tester — the NET-1 card (walk into the north wall) would have been RED for the same reason.

**Evidence**
- Wrote the engine check the spec already names, `OUT_COLL_01_EveryFloorHasCollision` (`UnitTests/OutpostTests.cs`), which builds the area with the real generator and traces down onto every walkable floor the layout declares.
- Before the fix: failed on 5 of 5 gate-apron samples, "nothing solid under the floor's top (z = 0)"; ground passed. That's the tester's report reproduced.
- After the fix: passes; all seven blocks now build `sbox_procedural_model.vmdl`.
- Full suite: 7/7 pass, no component errors in the engine log. `py -3 tools/spec_lint.py` passes.
- Added `OUT_COLL_01_Control_FloorWithoutCollisionIsDetected` — builds the outpost *without* the apron and requires the check to report it. The floor-vs-obstacle classification is a heuristic (top flush with the ground within a step height), so without this control the check could later pass by simply not looking at the apron.

Two things I did not do: the other four engine checks named in the spec (OUT-SPAWN-01, OUT-ROUTE-01, OUT-SIGHT-01) are still unwritten — out of scope for this bug, but the gate area is now the only part with an engine check. And this is proven headlessly; confirming it in a live session is the NET-1 card, which needs a person at a second client.
