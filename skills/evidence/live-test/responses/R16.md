## Final reply

`UnitTests/OutpostTests.cs` now holds the OUT-SPAWN-01 check, named after the spec's check (`OUT_SPAWN_01_EverySpawnLandsOnSolidGround`), plus two controls that prove it can fail.

```text
OUT-SPAWN-01  engine  pass (control RED)  0cbab29  both spawns land on ground with room to stand;
                                                   stuck-check control fails: generated blocks have no collision
```

**What the test does.** It builds the area with the project's own `OutpostGenerator.Build` from `spec/outpost.layout.json`, then for each listed spawn (a fresh scene per spawn) drops a headless `PlayerController` and reports every way that spawn breaks the requirement: never lands, lands somewhere other than the surface the *layout* puts under it, ends up inside geometry, or has no headroom for a standing body. The expected surface comes from the layout data (`SolidTopBelow`), not from where the player stopped, so the code isn't grading itself.

Results: `spawn.north` and `spawn.south` both land at z = 0.04 against an expected ground top of z = 0, body clear, 72 units of headroom.

**The control that's red, and why it matters.** `OUT_SPAWN_01_Control_SpawnInsideGeneratedGeometryIsDetected` places a player inside the generated tower; it must be reported as stuck. It isn't — the player falls through the tower and rests on the ground. A temporary diagnostic (since deleted) pinned the cause:

```text
wall.north … tower:  enabled=True  model=null  collisionMeshes=-1
tower ray:           hit=True  name=ground  z=0      ← ray passes through the tower
Diag Block (control) model=sbox_procedural_model.vmdl  collisionMeshes=1
```

Every block the generator makes has `Model = null`: no mesh, no collision. `OutpostGenerator.AddMeshBlock` (`Code/OutpostGenerator.cs:48`) creates the `MeshComponent` **enabled** and assigns `Mesh` afterwards, and in a game scene a `MeshComponent` builds its model only when it's enabled — the same trap `UnitTests/StarterGeometry.cs:43` warns about. So right now the walls, gate apron, and tower exist as objects with no geometry; only the ground `BoxCollider` is solid.

That makes the spawn test's pass narrower than it looks: the two spawns genuinely land on solid ground with room to stand, but the "not stuck inside geometry" half is currently vacuous, because there's no built geometry to be stuck in. The control is exactly what should stay red until that's fixed — I left the assertion as-is rather than weakening it.

The fix is one line in the generator (create disabled → assign `Mesh` → enable, as `StarterGeometry.CreateBlock` does), but it's game code and belongs to OUT-COLL-01's claim, so I didn't touch it. Want me to make that change and re-run, so the control goes green?
