## Final reply

Fixed. The generator was building its mesh blocks in the wrong order.

**Cause** — `OutpostGenerator.AddMeshBlock` created the `MeshComponent` already enabled and assigned `Mesh` afterwards. Outside an editor scene that assignment does nothing: the component never builds. `UnitTests/StarterGeometry.cs:44` already documents this, but the generator didn't follow it.

I proved it with a diagnostic that built the same box three ways in a real headless scene (ticked, so a deferred build would have shown up):

```
A (enabled, then collision+mesh): model=null   → trace hit=False
B (disabled, collision+mesh, enable): model=sbox_procedural_model.vmdl physMeshes=1 → trace hit=True
C (enabled, mesh, then collision): model=null  → trace hit=False
```

**Fix** — `Code/OutpostGenerator.cs:48`: create the component disabled, assign collision and mesh, then enable. This covers the tower and gate apron too, which were built the same way.

**Checks** — I wrote the missing engine check first and watched it fail for the right reason (`wall.north: a ray passed straight through the wall`), with a control that must report a miss through the gate opening, so a trace that hits everywhere can't fake a pass.

```
OUT-COLL-02  engine   pass   working tree   (was FAIL before the fix; control passes both ways)
OUT-DATA-01  static   pass   working tree   spec lint, 10 requirements well formed
(full engine suite: 7/7 passed, 0 component errors in the engine log)
```

Two things to flag:

- **OUT-COLL-02 is `draft`.** I added it to `spec/outpost.spec.md` because wall solidity had no automated check at all — it was only covered by the NET-1 session card, which is why this reached the game. Only you can mark it `agreed`.
- **One thing doesn't match your report.** You said the walls are visible; headlessly the broken order built *no* model, so there was nothing to render either. In a live game scene the render and physics paths may build differently, so what you saw may have come up visually while physics stayed empty. The collision claim is settled at the engine rung either way, but confirming in-game is still yours — card **NET-1** (host, join from a second client, walk into the north wall, then through the gate) is ready to run.

+	{
+		var across = size.x < size.y ? new Vector3( 1, 0, 0 ) : new Vector3( 0, 1, 0 );

+		var centre = min + size / 2;
+		centre.z = min.z + height;
+
+		var reach = across * (thickness / 2 + 64);
+		return scene.Trace.Ray( centre - reach, centre + reach ).Run();
+	}
