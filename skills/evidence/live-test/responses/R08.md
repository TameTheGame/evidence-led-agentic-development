## Final reply

Found and fixed it.

## What was wrong

`OutpostGenerator.AddMeshBlock` created the `MeshComponent` **enabled**, then assigned `Collision` and `Mesh` (`Code/OutpostGenerator.cs:48`). Outside an editor scene a `MeshComponent` builds its model only when it's enabled, so assigning the mesh afterwards did nothing — silently, with nothing in the engine log. Every mesh block came out with no geometry and no collision.

Why it only showed near the gate: the yard floor is a `BoxCollider` (`AddGround`), which spans y −800…800 and was never affected. The only walkable floor built as a mesh block is `gate.apron` (y −1024…−800), the ground just outside the south wall's gate gap. So the floor held everywhere except where players step out through the gate.

The starter's own `UnitTests/StarterGeometry.cs:43` documents the create-disabled → assign → enable pattern; the generator just didn't follow it.

## The fix

`Code/OutpostGenerator.cs` — create the component disabled, assign mesh and collision, then enable it.

## Evidence

I wrote the spec's missing engine check first (`UnitTests/OutpostTests.cs`), named after the requirement, and watched it fail for the right reason before changing any code — all 16 samples on `gate.apron` reported "nothing under it", while the yard ground passed. It reads the expected floors from `spec/outpost.layout.json`, not from the generator, and it has a control case that builds the area with the apron left out and must report it, so a pass isn't blind.

+	/// Every sampled point of a walkable floor where a ray straight down finds no surface at the

+	}

+	/// <summary>
+	/// Evenly spaced coordinates covering one inset side of a floor, no more than MaxStep apart.
+	/// </summary>
+	static IEnumerable<float> Spread( float min, float max )
+	{
+		var from = min + Inset;
+		var to = max - Inset;
+
+		if ( to <= from )
+		{
+			yield return (min + max) / 2;
+			yield break;
+		}

+		var steps = (int)MathF.Ceiling( (to - from) / MaxStep );
+		for ( int i = 0; i <= steps; i++ )
+			yield return from + (to - from) * i / steps;
+	}
