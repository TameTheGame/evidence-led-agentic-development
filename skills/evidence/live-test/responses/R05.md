## Final reply

Fixed. The tester is right, and the cause wasn't the layout data — it was the generator silently producing no collision.

**What was wrong:** `Code/OutpostGenerator.cs:48` created the `MeshComponent` enabled and then assigned `Mesh`. Outside an editor scene the mesh only builds on enable, so assigning afterwards does nothing — the engine doesn't throw, it just makes no collision. `StarterGeometry.cs:43` already documents this quirk; the generator didn't follow it.

Why it showed up *at the gate specifically*: the yard floor is a `BoxCollider`, which is unaffected. `gate.apron` — the slab outside the gate, y −1024…−800 — is the only walkable floor built as a mesh block, so it was the only floor with nothing under it. Walking out through the gate meant walking off collision entirely.

**Worth knowing:** the same bug stripped collision from the walls and the tower too, since they share `AddMeshBlock`. Players could have walked through the north wall as easily as through the apron. The fix is one code path, so all of them are restored.

**Changes:**
- `Code/OutpostGenerator.cs` — create the component disabled, assign the mesh, then enable it.
- `UnitTests/OutpostTests.cs` (new) — the spec's named check, plus its control.
- `README.md` — one stale line about no engine checks existing.
