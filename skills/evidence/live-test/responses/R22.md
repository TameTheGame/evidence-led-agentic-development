## Final reply

Fixed and proven at the engine rung.

**Rigor: evaluated** — the claim is live physics behavior, so it needed a real engine check with a control; the change itself is one file and an ordinary revert.

## Root cause

`OutpostGenerator.AddMeshBlock` created the `MeshComponent` already enabled and assigned `Mesh` afterwards:

```csharp
var block = go.Components.Create<MeshComponent>();   // enabled on creation
block.Mesh = BoxMesh( size );                        // too late — never builds
```

Outside an editor scene a `MeshComponent` builds its model only when it becomes enabled, so assigning the mesh later does nothing. No model means no collision mesh. The engine catches that silently — nothing throws, nothing appears in test output.

**Every one of the 7 mesh blocks was non-solid** — all five walls, the tower, and the gate apron. The yard floor is a `BoxCollider` (`AddGround`), which built fine, and that's why the tester saw it only at the gate: the gate apron is the sole *walkable* surface built as a mesh. Step off the ground slab at y = -800 and there is nothing under you. In the reproduction the player fell to z = -12501.

`Code/OutpostGenerator.cs:48` now creates the component disabled, assigns the mesh, then enables it — the same order `UnitTests/StarterGeometry.cs:45` already documented.
