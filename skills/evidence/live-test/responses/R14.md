## Final reply

Fixed. Root cause and evidence:

**Cause** — `Code/OutpostGenerator.cs:48` created the `MeshComponent` already enabled, then assigned `Collision` and `Mesh` afterwards. Outside an editor scene a `MeshComponent` builds its model only at the moment it is enabled, so assigning the mesh later did nothing: the walls, gate apron, and tower got no model and therefore no collision mesh. The ground was unaffected because it uses a `BoxCollider`, which is why players fell on the ground but walked through everything else.

**Fix** — create the component disabled, assign the mesh and collision type, then enable it (the same order `UnitTests/StarterGeometry.cs` already used).

**Checks** — new `UnitTests/OutpostTests.cs` drives the game's own `OutpostGenerator` over the real `spec/outpost.layout.json`:

| Claim | Rung | Result |
|---|---|---|
| Every generated block builds exactly one collision mesh | engine | pass (failed before the fix: "wall.north: no model was built") |
| A chest-height ray across each wall segment stops on that wall | engine | pass (failed before the fix: ray passed straight through) |
| Control: the same probe through the gate opening is *not* blocked | engine | pass before and after, so the wall check isn't hitting everywhere |

Full suite: 8/8 pass, 0 component errors in the engine log (`test-results/20261012-185507`). `spec_lint.py`: PASS. Nothing committed yet.

Two things for you:

- **The walls should also have been invisible**, not just non-solid — no model was built at all. If you were seeing solid-looking walls that you walked through, then something else was drawing them and I should look again; tell me which it was.
- **NET-1 is still open.** The engine rung proves collision exists in a headless scene; it can't prove what a remote client sees. Card NET-1 (host, join from a second client, walk into the north wall, then through the gate) is ready for you when you want to close OUT-NET-01.

I named the new checks after what they prove rather than after the spec's `OUT_COLL_01_EveryFloorHasCollision`, because that requirement says "every walkable floor" and the layout data has no floor/wall labels — I'd be guessing at what counts. Say the word (e.g. "walkable = the spawn points and route points") and I'll write that check properly too.
