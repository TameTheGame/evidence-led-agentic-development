## Final reply

Fixed.

## Cause

`Code/OutpostGenerator.cs:48` created the `MeshComponent` **already enabled**, then assigned `Collision` and `Mesh` afterwards. Outside an editor scene, `MeshComponent` builds its model only at the moment it's enabled — assigning `Mesh` later does nothing. No model means no physics shapes, so the walls rendered but had nothing to collide with. The engine doesn't throw for this; a missing `Model` is the only sign.

The project's own test helper already knew this and worked around it (`UnitTests/StarterGeometry.cs:43-48`); the generator just didn't follow the same order.

## Fix

`Code/OutpostGenerator.cs:48` — create disabled, assign, then enable:

```csharp
var block = go.Components.Create<MeshComponent>( false );
block.Collision = MeshComponent.CollisionType.Mesh;
block.Mesh = BoxMesh( size );
block.Enabled = true;
```

This covers all seven blocks, not just the walls — the gate apron and the tower had the same problem.

## Evidence

New `UnitTests/OutpostTests.cs` drives the real `OutpostGenerator` over `spec/outpost.layout.json`:

- `OUT_COLL_BLOCKS_01_EveryGeneratedBlockBuildsCollision` — every block has a built `Model` with exactly one collision mesh.
- `OUT_COLL_WALLS_01_WallsBlockAPlayerBody` — a player body swept into each wall is stopped by that wall.
- `OUT_COLL_WALLS_01_Control_GateOpeningIsPassable` — control: the gate gap still lets a body through, so a trace that hits everything can't make the wall test pass.

Results, all on S&box 26.10.02:
- With the fix reverted: `Passed: 1 | Failed: 2` — both collision tests fail, control passes.
- With the fix: all 3 pass; full suite `Total tests: 8 | Passed: 8`, 0 component errors in the engine log.
- `py -3 tools/spec_lint.py` — PASS.

That's the reason this shipped, and the other three requirements are currently unproven.
