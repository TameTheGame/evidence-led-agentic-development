## Final reply

The test is written and run. It found a real bug, so OUT-SPAWN-01 is **not** settled.

```text
OUT-SPAWN-01  engine   FAIL   working tree (UnitTests/OutpostSpawnTests.cs, uncommitted)
                              cause: generator mesh blocks have no collision; control RED
```

**What I added** — `UnitTests/OutpostSpawnTests.cs`, three tests that build the outpost with the game's own `OutpostGenerator` from `spec/outpost.layout.json` (expected heights come from the layout file, never from the generator):

- `OUT_SPAWN_01_EverySpawnLandsOnSolidGround` — the spec's named check. Per spawn, in its own scene: it grounds within the tick budget, rests between the layout's ground top and its spawn z, and its standing body isn't inside geometry. **Passes.**
- `OUT_SPAWN_01_Control_PlayerInsideTowerIsDetected` — a player buried in the tower must be reported stuck. **Fails.**
- `OUT_SPAWN_01_Control_SpawnOverVoidDoesNotLand` — a player dropped past the ground's edge must not ground. **Passes.**

**The bug.** The walls, gate apron, and tower are not solid in a running scene. A throwaway diagnostic showed every generated block with `Model = null` and zero collision meshes, and a ray straight down the tower axis hitting nothing. The engine log recorded no component errors — nothing threw, the mesh just never built.

The cause is `Code/OutpostGenerator.cs:48-50`: it creates the `MeshComponent` already enabled, then assigns `Mesh`. Outside an editor scene a `MeshComponent` builds only as it's enabled, so a mesh set afterwards is ignored — the behaviour documented at `UnitTests/StarterGeometry.cs:44`, which creates the component disabled, assigns the mesh, then enables it. The starter's own controls pass, which is what isolates this to the generator rather than the stuck-detector.

**What this means for the requirement.** The green on the main test only proves the spawns land on the ground `BoxCollider`, which is built correctly; both spawns sit in open yard. Its room-to-stand half is currently blind, because there's no wall or tower collision for a body to be inside of. I've left the control red rather than weakening it — the test will go green on its own merits once the geometry is solid.

The fix looks like a three-line reorder in `AddMeshBlock`, but it's game code under OUT-COLL-01 rather than the test you asked for, and it would change the generator the game runs. Want me to make it? Once it's in, this test's control should flip to green and OUT-COLL-01 becomes worth writing too.
