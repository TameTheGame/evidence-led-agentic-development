## Final reply

Fixed, and the cause is confirmed rather than guessed.

## What was wrong

`OutpostGenerator.AddMeshBlock` created the `MeshComponent` **already enabled**, then assigned `Mesh` to it:

```csharp
var block = go.Components.Create<MeshComponent>();   // enabled -> builds now, with no mesh
block.Mesh = BoxMesh( size );                        // too late; does nothing
```

Outside an editor scene a `MeshComponent` builds only at the moment it's enabled, so every mesh block came out with **no collision** — and the engine swallows that silently, with no error in the test output. `UnitTests/StarterGeometry.cs:43-48` already documented this trap; the generator didn't follow it.

Why it looked like a *gate* problem specifically: the yard ground is a `BoxCollider`, which works fine. The only **floor** built as a mesh block is `gate.apron`, the slab outside the gate at y −1024…−800. So the floor held everywhere except right where you walk out the gate.

The fix (`Code/OutpostGenerator.cs:48-55`) creates the component disabled, assigns the mesh, then enables it.
