## What I wrote

Eight requirements in `spec/outpost.spec.md`, all `draft`, plus two cards. "Players can climb the tower" isn't one claim — it's seven at different rungs:

| ID | Rung | Claim |
|---|---|---|
| OUT-CLIMB-01 | static | layout describes an unbroken climb, base to top |
| OUT-CLIMB-02 | engine | every rung/tread/landing has collision |
| OUT-CLIMB-03 | engine | the real controller can actually get up without sticking |
| OUT-CLIMB-04 | engine | headroom at every stage and at the top |
| OUT-CLIMB-05 | engine | the top platform holds a standing player |
| OUT-CLIMB-06 | engine | you can climb back down |
| OUT-CLIMB-07 | session | a remote client climbs, and both machines agree where they are |
| OUT-CLIMB-08 | owner | the way up is obvious, and the climb fits the outpost |

OUT-CLIMB-02 exists separately from OUT-COLL-01 because that one covers *walkable floors*; rungs and treads are separate geometry. OUT-CLIMB-03 exists separately from OUT-ROUTE-01 because that requirement's own `why` says slopes and stairs need a walk test instead. I didn't add an editor-rung requirement — OUT-SAVE-01 already covers the whole generated scene, climb geometry included.

All eight are `draft`, not `agreed`. `DECISIONS.md` has *"Make an informed decision on my behalf"*, which is consent without scope or an end date — the project's own `[skill]` guidance treats that as not a hand-off, so agreeing these is still yours. Nothing here is built or checked yet; these are requirements only, and the layout file is untouched.

## Four things I need from you

I put these in an **Open questions** section in the spec so they outlive this chat:

1. **Ladder or stairs?** A ladder reads as a frontier water tower and stays out of an interior (out of scope), but relies on ladder support in PlayerController. Exterior switchback stairs are safer for movement and need no ladder code. **I'd go stairs** unless the ladder look matters more to you.
2. **The top doesn't currently fit a player.** The tower top is at z 480 and the layout bounds stop at z 512 — 32 units of headroom, under standing height. So either the bounds rise, the tower top drops, or the top is a crouch-only perch. This also touches OUT-SIGHT-01, which aims at that same point. This is the one that needs an answer before anything gets built.
3. **Should a fall from the top hurt?** OUT-CLIMB-06 only asks that climbing down works.
4. **Is the climb always open,** or gated behind something later?

Question 2 is a conflict in the existing agreed data, not something I introduced — worth a look even if the climb gets deferred.

The spec edit is uncommitted; say the word if you want it on a branch.
