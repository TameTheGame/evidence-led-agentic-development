## Final reply

I did not fix the sign, and I want to be straight about why rather than ship a guess.

**What I found.** `Code/GateDecal.cs` sets the sign's rotation from a constant, and hands one `DecalDefinition` to a `Decal` component. A constant rotation can't vary per load, and a one-item list can't be randomly picked from — so nothing in the code can produce a different angle each time. The variance has to come from the decal placement itself, i.e. from `decals/outpost_sign.decal`. In S&box, `DecalDefinition` is the impact-decal type, where randomized placement is the whole point; if that asset carries a rotation range, the sign inherits the randomness and **no code change will fix it**.

I couldn't confirm that here: this environment has no S&box install and no clone of `Facepunch/sbox-public` (per `AGENTS.md`), and `decals/outpost_sign.decal` isn't in the repo — `Assets/` holds only the two scene files. So I can't read the declaration, can't compile, and can't watch the symptom. I deliberately left `GateDecal.cs` alone: the one edit I was tempted by (passing an explicit up vector to `Rotation.LookAt`) is most likely a no-op, and if it isn't, it would change the roll of a sign I can't see, in code I can't build.
