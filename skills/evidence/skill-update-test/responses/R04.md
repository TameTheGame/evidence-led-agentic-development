## Final reply

Done. Here's where it stands.

## The fix

`Code/GateDecal.cs` set the sign's angle with the one-argument `Rotation.LookAt( Vector3.Forward )`. That names the forward axis but leaves the roll *about* that axis to an implicit up vector, so the code never actually pinned the angle down. I made both axes explicit:

```csharp
go.WorldRotation = Rotation.LookAt( Vector3.Forward, Vector3.Up );
```

That is the only place anything sets the sign's rotation — the sign is created entirely in code, and the scene file carries no rotation for it (`outpost.scene:176-190` has the `GateDecal` component and nothing else).

## The recurrence guard

- `UnitTests/GateSignTests.cs` — `OUT_SIGN_01_SignRotationIsStableAcrossLoads` loads the outpost scene 5 times and asserts the sign's world rotation is identical across loads. It asserts the sign object *exists* on each load, so it can't pass by comparing nothing. It deliberately doesn't hard-code an angle — the spec'd property is "stays put", and hard-coding would just grade the code against itself.
- `spec/outpost.spec.md` — added `OUT-SIGN-01` and owner card `SIGN-1`. I left the requirement `state: draft`; only you mark something `agreed`.
