## Final reply

Rigor: **bounded** — a one-call fix plus a new guard, ordinary revert, but nothing here can compile or run S&box code, so the proof hands off to you.

## What I changed

**`Code/GateDecal.cs`** — the sign's rotation was `Rotation.LookAt( Vector3.Forward )`: a facing direction with nothing said about which way is up, so the roll around that direction was the engine's to pick. Every other input to the sign is a literal constant, so it was the only thing in that code that could vary per load. It now names both axes:

```csharp
go.WorldRotation = Rotation.LookAt( Vector3.Forward, Vector3.Up );
```

I kept the facing direction exactly as it was — see the question below.

**So we don't get caught again**, three things:
- `UnitTests/GateSignTests.cs` — `OUT_SIGN_01_SignLoadsAtTheSamePlaceAndAngle` starts the component in five fresh scenes and requires the same upright transform every time. Expected values come from the requirement (upright; every load matches the first), not copied from `GateDecal`. The component now exposes `SignObject` so a check can read where the sign ended up.
- `spec/outpost.spec.md` — new `OUT-SIGN-01`, state **draft** (only you mark it agreed), rung engine, plus card SIGN-1 for the in-game look.
- `docs/engine-lessons.md` — new, with the rule this left: when you set an orientation, name every axis; an input the API lets you leave out is a free variable, and free variables move.
