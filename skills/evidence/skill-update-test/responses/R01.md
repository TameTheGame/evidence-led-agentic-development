## What I found

`Code/GateDecal.cs` had a real bug on the rotation line, but **it isn't the one you're seeing**:

```csharp
go.WorldRotation = Rotation.LookAt( Vector3.Forward );   // points the sign down +X — east
```

`Vector3.Forward` is a constant and `Rotation.LookAt` is a pure function of its arguments, so whatever its default `up` is, that line can only ever produce *one* angle. It was the wrong angle — east, while the gate gap in the south wall faces −Y — but it was wrong the same way every load.

So the per-load variation comes from the decal path, not from your code: either the `Decal` component's placement or, much more likely, the `decals/outpost_sign.decal` definition itself. Decal definitions are built for impact marks, which are *meant* to land at a random angle. **That asset isn't in the repo** (`git ls-files | grep -i decal` returns only `Code/GateDecal.cs`), so I can't read it, and per `AGENTS.md` there's no S&box install or engine-source clone here — I couldn't check the engine declarations either.

## What I changed

- **`Code/GateDecal.cs`** — the rotation is now explicit in both axes (`(0,1,0)` forward, `(0,0,1)` up), projecting north into the south wall's outer face, with a comment explaining the placement. This fixes the wrong angle and removes any dependence on an API default.
- **`spec/outpost.spec.md`** — new `OUT-SIGN-01`, *draft*, engine rung. Draft because only you agree a requirement; it also carries a `limit:` line for the blind spot below.
- **`UnitTests/OutpostSignTests.cs`** — `OUT_SIGN_01_SignAngleIsFixedEveryLoad`: loads the scene five times, ticks so `OnStart` runs, and asserts the `gate.sign` rotation is identical across loads *and* equals the angle the spec asks for. The expected value is written out in the test rather than read from `GateDecal`, so the code doesn't grade itself.

## Two things I can't close, and won't pretend to

1. **The fix may not fix your symptom.** If the random angle lives in the `.decal` definition, setting `WorldRotation` won't stop it — and the new test would be blind to it too, since it reads the GameObject's rotation, not whatever the renderer does afterwards.

+using System.Linq;
+using Microsoft.VisualStudio.TestTools.UnitTesting;
+using Sandbox;
+
+namespace EngineTests;
+
+/// <summary>
+/// OUT-SIGN-01 — the gate sign is at the same angle on every load.
+/// </summary>
+[TestClass]
+public class OutpostSignTests
+{
+	const string ScenePath = "Assets/scenes/outpost.scene";
+
+	// The angle the spec asks for, written out here rather than read from GateDecal, so the
+	// code under test doesn't supply its own expected answer: the sign faces north (+y),
+	// projecting into the south wall's outer face, and stands upright.
+	static readonly Vector3 ExpectedForward = new( 0, 1, 0 );
+	static readonly Vector3 ExpectedUp = new( 0, 0, 1 );
+
+	// Loads to compare. The failure this guards against is a fresh random angle per load, so
+	// one load can't show it.
+	const int Loads = 5;
+
+	[TestMethod]
+	public void OUT_SIGN_01_SignAngleIsFixedEveryLoad()
+	{
+		var seen = new Rotation[Loads];
+
+		for ( int i = 0; i < Loads; i++ )
+		{
+			using var scene = new Scene();
+			using ( scene.Push() )
+			{
+				Assert.IsTrue( EngineTestHelpers.LoadSavedScene( scene, ScenePath ),
+					$"load {i + 1}: the outpost scene did not load" );
+
+				// GateDecal places the sign in OnStart, which runs on the first tick.
+				scene.GameTick();
+
+				var sign = scene.GetAllObjects( true ).FirstOrDefault( o => o.Name == "gate.sign" );
+
+				// GateDecal sets the object's transform before it touches the decal resource, so
+				// the sign is placed even if the decal itself fails to load headlessly. A missing
+				// object means OnStart didn't run or threw first: read logs\testhost.log in the
+				// S&box install folder, where caught component errors go.
+				Assert.IsNotNull( sign, $"load {i + 1}: no \"gate.sign\" object was created" );
+
+				seen[i] = sign.WorldRotation;
+			}
+		}
+
+		// Same angle every load.
+		for ( int i = 1; i < Loads; i++ )
+			Assert.AreEqual( Describe( seen[0] ), Describe( seen[i] ),
+				$"the sign's angle changed between load 1 and load {i + 1}" );
+
+		// And the angle the spec asks for, not just a consistently wrong one.
+		Assert.AreEqual( Describe( Rotation.LookAt( ExpectedForward, ExpectedUp ) ), Describe( seen[0] ),
+			"the sign is not facing north (+y) and upright" );
+	}
+
+	/// <summary>
+	/// A rotation as its rounded forward and up axes. Comparing axes rather than quaternion
+	/// components keeps an equivalent rotation written a different way from failing, and the
+	/// rounding absorbs float noise while still catching any real change in angle.
+	/// </summary>
+	static string Describe( Rotation rotation ) =>
+		$"forward {Round( rotation.Forward )} up {Round( rotation.Up )}";
+
+	static string Round( Vector3 v ) =>
+		$"({v.x:F3}, {v.y:F3}, {v.z:F3})";
+}
