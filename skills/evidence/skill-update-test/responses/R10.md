## What I wrote

`UnitTests/OutpostSceneTests.cs` — `NorthSpawnLandsOnSceneGround`. It loads the saved scene through the existing `EngineTestHelpers.LoadSavedScene`, which is the part that matters here: that helper routes through the editor's internal `SceneFile.FromSource` so the `outpost.scene_d` blob comes with it. Via the public `LoadFromJson` the ground mesh would load empty and the player would fall straight through a test that still looked green.

It then finds `spawn.north` in the loaded scene (not the layout file — the scene is the subject), puts a headless player there, and asserts four things in order:

1. the scene loaded;
2. the player **didn't** start inside geometry — a player buried in the ground reports grounded too, so without this the landing assert can't fail for the right reason;
3. it became grounded within the helper's 60-tick bound;
4. it came to rest inside the layout's `bounds`, and `GroundObject` is the scene's `ground` — not a wall top or the tower.

Two deliberate omissions. I don't assert a landing **height**: you reshaped that ground by hand, so the layout no longer says how high it is, and any number I could get would come from reading this scene back — grading itself. And I didn't name it `OUT_SPAWN_01_EverySpawnLandsOnSolidGround`; that requirement is agreed against the layout and generator and covers *every* spawn with room to stand, which isn't what you asked for.

+	const string Ground = "ground";
