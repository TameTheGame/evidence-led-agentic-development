## Final reply

Written to `UnitTests/SpawnTests.cs:1`. The check name matches the spec exactly: `OUT_SPAWN_01_EverySpawnLandsOnSolidGround`.

**How it works.** It builds the real scene headlessly (`new Scene()` → `OutpostGenerator.Build`), then for each spawn in the layout: drops a ray to find the floor, and stands a 72×16 player hull on that floor to check nothing is in the way. The expected spawn positions come from `spec/outpost.layout.json`, not from the generator, so the generator isn't grading itself.

The spec sentence is two claims, so the test reports them separately — "nothing solid within 64 units below it" vs "lands at X but a standing player overlaps wall.north" — because the fixes are different.

**Proving it can fail.** I can't run it here (no S&box install, per AGENTS.md), so I couldn't watch it go red myself. Instead I baked the negative control in as a second test, `OUT_SPAWN_01_CheckRejectsBadSpawns`, which your normal `dotnet test` run exercises:

- a hull at `(0, 760, 8)` clips 8 units into `wall.north` → must fail room-to-stand
- a spawn at `(0, 900, 8)` is past the ground's edge → must fail solid-ground

If either comes back green, the real check is blind. The first one also only fails if the walls' **mesh** collision actually built — the part most likely to go missing quietly.

There's also a `AssertSceneHasCollision` guard that traces down the middle of the yard first. If that's the line that goes red, the test setup is wrong, not your layout.

**Expected result.** Both layout spawns should pass. I checked the arithmetic by hand against the layout boxes: both sit at z=8 over ground whose top is z=0, and the nearest wall is 168 units from the north spawn, far outside the hull's 16-unit radius.

**Two things I could not verify, both compile-time:**

1. The trace API spelling — `scene.Trace.Capsule( capsule, from, to )`, `Capsule(a, b, radius)`, `SceneTraceResult.StartedSolid`. I matched the engine API style the generator already uses, but without the engine or its source here I couldn't confirm these signatures. If the build errors on one, send me the error and it's a quick fix.
2. Whether `UnitTests/` compiles `Code/OutpostGenerator.cs`. The existing tests never reference it, and there's no `.csproj` tracked in git, so I couldn't check. If you get "OutpostGenerator could not be found", that's a project reference to add rather than a problem with the test.

I also didn't add a scene tick before tracing. Colliders should register on creation, and I'd rather not call an API I can't verify — the guard above turns that guess into a clear message if it's wrong.
