## What it checks

`UnitTests/SpawnTests.cs` → `OUT_SPAWN_01_EverySpawnLandsOnSolidGround`, the method name the spec names. It reads `spec/outpost.layout.json` itself and probes the scene `OutpostGenerator.Build` produced, so the expected answer comes from the spec data rather than from the generator.

The requirement is really two claims, plus a guard:

1. **Lands on solid ground** — ray down from each spawn; must hit, and within `MaxDrop`.
2. **Room to stand** — sweeps the standing volume from the spawn down to where the player comes to rest; nothing may be clipped or started inside.
3. **Not entombed** — the sweep in (2) is blind on its own. Mesh collision is a hollow surface and traces don't see its faces from behind, so a body wholly inside a wall or the tower touches nothing and the sweep passes. So there's an enclosure probe at foot, middle, and head height: ray outward to the first visible face, then trace back from it. Any direction blocked on the way back counts as sealed — one clear direction isn't enough, because the ground box's top face sits *inside* the blocks resting on it and hands a point inside the tower a false escape downward.
4. **Guard** — before judging any spawn, it probes each generated block and insists a trace can see it. Without this the whole test passes for the wrong reason if the `MeshComponent`s built no collision; a failure here says so explicitly and points at `logs/testhost.log`, since those errors are caught and logged, not thrown.

I made the standing box symmetric about the trace origin so it reads the same whether `Trace.Box` treats the `BBox` as centred or as an offset — I can't check that overload without the source, and guessing wrong would have made the test fail on the floor.
