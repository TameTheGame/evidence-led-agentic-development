## Final reply

## The cause

`AddMeshBlock` created the `MeshComponent` **enabled**, then assigned `Collision` and `Mesh` to it:

```csharp
var block = go.Components.Create<MeshComponent>();   // already enabled here
block.Collision = MeshComponent.CollisionType.Mesh;
block.Mesh = BoxMesh( size );                        // too late
```

In a game scene a `MeshComponent` builds its model — and with it its collision shapes — only as it becomes enabled, and assigning `Mesh` to an already-enabled component doesn't rebuild it. Every block went through this path, so no wall, the gate apron, or the tower ever got collision. The ground still collides because it's a `BoxCollider`, not generated mesh, which is why the floor behaves and the walls don't.

`Code/OutpostGenerator.cs:48` now creates it disabled, fills it in, and enables it last.

## Evidence

The spec named `OUT_COLL_01_EveryFloorHasCollision` as an agreed check but it was never written, so there was nothing that could have caught this. I wrote it, plus a wall check, in `UnitTests/CollisionTests.cs`:

- **`OUT_COLL_01_EveryFloorHasCollision`** — traces down from every spawn and every route point and expects solid floor below. It takes the floor points from the layout's own spawns and routes rather than guessing which block is a floor.
- **`OUT_COLL_02_WallsStopAPlayer`** — sweeps a standing player hull from inside the yard out through the middle of each `wall.*` block and expects that wall to stop it. This is your actual report; OUT-COLL-01 wouldn't have caught it, since walls aren't floors.

OUT-COLL-02 is a new requirement, so it's in the spec as `draft` — only you mark it agreed.
